# Shared dispatch

Read once per assignment alongside the selected mode.

Pure orchestration delegates substantive work. Supporting delegation permits requested direct execution. Retain choices through compaction. Variant selects pool preference, not host. Never change the parent model.

## Selection and authority

Honor explicit profiles and active bindings. Slots define distinct jobs, not stages or worker counts. Rebinding preserves roles, lifecycle, and review authority. Task fit expresses preference, not measured effort-specific specialty.

Choose the earliest suitable eligible slot, not a cheap-first sequence. General slots permit all roles. One-off slots require fresh bounded workers, never continuing controllers. Specialist slots take precedence for their role, without banning others' tools. Role-restricted reviewers do not preempt general candidates solely on task fit.

Role/lifecycle exceptions require user authorization and an exact profile. Out-of-pool choices also require a pool exception. Inspector flags `--role-override` and `--allow-out-of-pool` record exceptions, not authority. Never import another mode's fences or substitute unavailable routes except the conditional Fable fallback.

Use native workers for the host provider with exact model/effort and verified tools/session access. External Codex under Claude uses the optional [controller adapter](../../../docs/controller-designs.md), subject to mode-specific designs.

Give workers objectives, inputs, disjoint write ownership, acceptance checks, profiles, and deadlines. Sequence dependent or overlapping writes. The controller integrates and accepts with author-independent checks. Reviewers need reassignment to fix. Analysis or tools do not authorize implementation or external mutations.

Repository investigation handoffs list source locations, key constraints, edge cases, and unverified items.

Preserve host permissions and selected tools, approvals, timeouts, and account routes. Routing imposes no permission policy. Broader checks require profile selection, not silently widened access. Never change accounts, global settings, or capacity automatically.

## Capacity and completion

Honor runtime, provider, project, and assignment-wide caps across descendants. Positive `max_parallel_workers` counts workers. Positive `max_external_sessions_per_assignment` counts all active external runs, including Muse and durable T3. Native workers consume only worker capacity. Idle threads do not count. Null/omitted caps add no ceiling or allocation requirement.

Claude helpers may delegate within inherited permissions, tools, role, pool, scope, ownership, and isolation. Pass variant, mode, bias, fences, remaining budgets, limits, and allocations. Split allocations without cloning. Request capacity only for capped resources. An external-session cap does not gate uncapped native workers. Native Codex workers remain leaves unless assigned team roles. External workers cannot launch opposite controllers. Helpers add no votes, diversity, or coordinators.

Preserve lifecycle, cancellation ownership, completion handling, and shared deadlines across continuations. Prefer completion events. Verify exact session ownership and delivery before promising continuation.

- Look up discoverable details. Record reversible in-scope assumptions and continue. Escalate only evidence-backed blockers or decisions materially affecting scope, authority, risk, or outcome.
- For sustained work, checkpoint the candidate, changes, verified results, ruled-out hypotheses, and remaining work. Without a useful next test, changed hypothesis, or concrete deliverable, reframe or hand off.
- Diagnose product, evaluator, infrastructure, provider, or authority failures before escalating. Retry only with changed inputs, supported transient conditions, or new diagnostic hypotheses.
- Transfer evidence only while its assumptions hold. Run affected and required checks. Preserve candidate identity, mode-required fresh independent reviews, and same-version ratification.
- Keep controls proportional to actual risks and requirements. Finish after acceptance and verification. Continue independent ready work around blockers.

Use fresh native workers or provider sessions for independent reviews. Exclude author/reviewer conversations and prior verdicts from fresh reviews. Check loaded memory and project context. Isolate per session. Disclose unresolved contamination without claiming independence. Mode protocols govern debate, ratification, and informed critique, which are not fresh reviews. Targeted verification is not independent acceptance or a vote.
